## 1. 프로젝트 개요

### 1.1 프로젝트 소개

DemandLab은 사업자가 상품의 강점과 타깃 고객을 설정하고, AI가 이를 바탕으로 리뷰단의 실제 사용 테스트 및 리뷰 작성 가이드를 생성하며, 제출된 리뷰를 자동 검수하고 피드백하는 AI 기반 리뷰단 운영 서비스입니다.

기존 고객 리뷰에서 발견한 주요 강점·약점과 고객 관심사를 분석하고, 이를 사업자가 강조하고 싶은 상품 특징 및 타깃 고객 정보와 결합하여 효과적인 리뷰 가이드를 생성합니다.

이후 작성된 리뷰가 가이드에서 요구한 평가 항목을 충분히 다루는지 확인하고 구체적인 보완 피드백을 제공합니다.

### 1.2 프로젝트 목표

상품의 실제 강점과 차별점이 타깃 고객에게 구체적이고 신뢰할 수 있게 전달되도록 리뷰단의 작성 가이드와 검수 과정을 AI로 지원합니다.

본 서비스는 특정한 긍정적 평가를 강요하거나 허위 리뷰를 생성하는 것을 목표로 하지 않습니다.

실제 사용 경험을 바탕으로 상품의 특징을 구체적으로 확인하고 설명하도록 지원하는 것이 핵심입니다.

### 1.3 주요 사용자

- 리뷰단을 운영하는 사업자
- 상품 마케팅 담당자
- 리뷰 캠페인 운영 담당자

### 1.4 개발 목적

2026년 2학기 DevDay 수업 시연용 웹서비스

실제 대규모 리뷰단 운영보다는 주요 AI 기능과 전체 서비스 흐름이 정상적으로 작동하는 MVP 구현을 우선합니다.

## 2. 핵심 기능

DemandLab의 핵심 기능은 다음 세 가지입니다.

### 2.1 상품·타깃 분석

사업자가 상품 정보와 강조하고 싶은 강점, 목표 고객층을 입력하고, 필요하면 기존 리뷰를 분석합니다. 현재 AI 분석은 리뷰 본문만 사용하며 상품 정보 기반 분석 및 AI 평가 항목 추천은 아직 구현되지 않았습니다.

**입력 정보**

- 상품명
- 상품 설명
- 상품의 주요 특징
- 사업자가 강조하고 싶은 강점
- 목표 고객층
- 기존 고객 리뷰 CSV 파일 (선택)

**주요 기능**

- 기존 리뷰의 주요 주제 추출
- 주제별 긍정·부정 반응 분석
- 리뷰 근거에 기반한 고객 관심사 및 불편 사항 탐색
- 사업자가 평가 항목을 직접 추가하거나 리뷰 분석 주제에서 선택

**출력 결과**

- 사업자가 입력한 상품·타깃 정보
- 사업자가 직접 관리하는 핵심 평가 항목
- 기존 리뷰 분석 결과

기존 리뷰 데이터가 없는 신규 상품도 분석 및 가이드 생성이 가능하도록 설계합니다.

### 2.2 AI 리뷰 가이드 생성

상품·타깃 분석 결과를 바탕으로 리뷰단에게 전달할 테스트 및 작성 가이드를 생성합니다.

**주요 기능**

- 상품 특징별 테스트 항목 추천
- 타깃 고객별 사용 상황 제안
- 실제 사용 시 확인할 항목 생성
- 리뷰 작성에 필요한 정보 안내
- 평가 항목 체크리스트 생성
- 생성된 가이드 수정
- 가이드 저장 및 다운로드

**출력 결과**

- 리뷰단 테스트 가이드
- 리뷰 작성 가이드
- 평가 항목 체크리스트

가이드는 긍정적인 평가를 요구하는 방식이 아니라 실제 제품 사용 결과를 구체적으로 기록하도록 안내하는 방식으로 생성합니다.

### 2.3 AI 리뷰 검수·피드백

작성된 리뷰를 저장된 리뷰 가이드와 비교하여 작성 기준 충족 여부를 확인합니다.

**입력 방식**

- 리뷰 한 건 직접 입력
- 리뷰 CSV 파일 일괄 업로드

**주요 기능**

- 가이드 평가 항목 충족 여부 확인
- 사용 경험의 구체성 평가
- 누락된 정보 탐지
- 불명확한 표현 탐지
- 리뷰별 보완 피드백 생성
- 검수 결과 목록 표시
- 검수 결과 저장
- CSV 다운로드

**출력 결과**

- 리뷰별 검수 상태
- 충족한 평가 항목
- 누락된 평가 항목
- 구체적인 보완 피드백

AI 검수는 작성된 텍스트를 바탕으로 판단합니다.

따라서 실제 제품 사용 여부나 리뷰 내용의 진실성을 자동으로 증명할 수는 없습니다.

## 3. 전체 서비스 흐름

1. 사업자가 상품 프로젝트를 생성합니다.
2. 상품명, 특징, 강조할 강점, 목표 고객층을 입력합니다.
3. 필요하다면 기존 리뷰 CSV를 업로드합니다.
4. AI가 상품 정보와 기존 리뷰를 분석합니다.
5. AI가 리뷰단 테스트 및 작성 가이드를 생성합니다.
6. 사업자가 가이드를 확인하고 수정합니다.
7. 리뷰단이 실제 사용 경험을 바탕으로 리뷰를 작성합니다.
8. 사업자가 작성된 리뷰를 업로드합니다.
9. AI가 저장된 가이드를 기준으로 리뷰를 검수합니다.
10. 사업자가 검수 결과와 피드백을 확인합니다.
11. 분석 결과, 가이드, 검수 결과를 프로젝트에 저장합니다.

서비스의 세 가지 핵심 단계는 서로 연결되며, 이전 단계의 결과를 다음 단계에서 활용합니다.

- 저장 모듈을 UI와 분리 (향후 서버 데이터베이스로 교체 가능)

## 5. AI 모델 이중 지원 구조

기존 리뷰 주제·감정 분석, 리뷰 가이드 생성 및 리뷰단 초안 검수는 OpenAI API 또는 로컬 Ollama 중에서 선택할 수 있습니다. 상품·타깃 전용 AI 분석 작업은 아직 연결되지 않았습니다.

### 5.1 OpenAI API

**구현 상태**

공통 `/api/analyze` 요청을 통해 리뷰 주제·감정 분석을 호출합니다. 기본 모델은 `gpt-4.1-mini`입니다. 연결 설정에서 API 키를 입력하고, 모델 목록 조회 및 연결 테스트를 수행할 수 있습니다.

**주요 특징**

- OpenAI 서버를 통한 AI 분석
- API 키 필요
- 사용량에 따른 비용 발생
- 인터넷 연결 필요

**현재 지원하는 기능**

- 기존 리뷰 주제 및 감정 분석
- 주제·하위 주제와 실제 원문 근거 반환
- 긍정·부정·중립·혼합 분류

API 키는 현재 탭의 메모리에만 두며 브라우저 저장소나 프로젝트 데이터에 저장하지 않습니다.

### 5.2 Ollama

**구현 상태**

로컬 `pnpm dev` 서버 API가 Ollama의 `http://127.0.0.1:11434`에 요청하여 설치 모델 목록을 조회하고, 선택한 모델로 기존 리뷰 분석을 수행합니다.

**주요 특징**

- 사용자 컴퓨터에서 AI 모델 실행
- OpenAI API 키 없이 사용 가능
- 로컬 컴퓨터의 하드웨어 성능에 영향받음
- 모델을 사전에 설치해야 함

**현재 지원 기능**

- Ollama 서버 연결
- 로컬 모델 선택
- 서버 연결 상태 확인
- AI 분석 요청
- 기존 리뷰 분석 지원
- 연결 실패 시 오류 안내

Ollama 서버 주소는 보안을 위해 이 로컬 주소로 고정하며, 임의 외부 주소를 API에 전달하지 않습니다.

`http://127.0.0.1:11434`

Cloudflare Worker 배포 환경의 `127.0.0.1`은 사업자 컴퓨터를 가리키지 않습니다. 배포 서비스에서 사용자 PC의 Ollama를 원격으로 호출하는 기능은 제공하지 않습니다.

### 5.3 공통 AI 인터페이스

OpenAI API와 Ollama는 서로 다른 호출 방식을 사용하지만, 제공자 모듈은 같은 리뷰 분석 요청·응답 타입을 사용합니다.

공통 AI 작업 유형:

1. 상품·타깃 분석
2. 기존 리뷰 분석
3. 리뷰 가이드 생성
4. 리뷰 검수 및 피드백

AI 제공자별 API 호출 로직은 분리합니다.

AI 분석 결과는 동일한 데이터 구조로 변환하여 프론트엔드에 전달합니다.

각 작업 응답은 공통 파서에서 JSON 구조와 필수 필드를 검증합니다. 리뷰 분석은 리뷰 ID·감정·실제 원문 근거를, 가이드 생성은 평가 항목·관계 공개 안내·안전한 테스트 방법을 확인합니다. 리뷰 검수는 현재 프로젝트의 저장 가이드와 리뷰 본문만 받아 평가 항목 ID, 상태 값, 입력 리뷰 ID, 정확한 원문 인용을 확인하고 전체 상태를 서버에서 계산합니다. 상품·타깃 전용 AI 분석 작업은 타입만 준비되어 있습니다.

### 5.4 AI 연결 설정

설정 화면에서 다음 항목을 선택할 수 있습니다.

**AI 제공자**

- OpenAI API
- Ollama

**OpenAI 선택 시**

- API 키 입력
- 설치 모델 목록 조회와 모델 선택
- 연결 테스트 및 상태 표시

**Ollama 선택 시**

- 보안상 고정된 로컬 서버 주소 표시
- 설치된 로컬 모델 목록 조회 및 모델 선택
- 연결 테스트 및 상태 표시

제공자와 모델 이름만 IndexedDB `settings` 스토어에 저장합니다. API 키는 저장하지 않습니다. 제공자를 바꾸어도 상품 프로젝트나 분석 결과는 삭제되지 않습니다. 연결 결과에는 선택 제공자·모델·실행 시각을 기록합니다.

### 5.5 AI 모델 비교

향후 동일한 입력 데이터를 사용하여 OpenAI와 Ollama의 성능을 비교할 수 있도록 합니다.

비교 항목:

- 처리 속도
- 분석 결과의 정확성
- 결과의 구체성
- JSON 출력 안정성
- 가이드 생성 품질
- 리뷰 검수 품질

모델 비교는 핵심 기능 완성 이후 진행합니다.

## 6. 데이터 저장 설계

### 6.1 저장 방식

현재 React 상태에만 데이터를 저장하는 구조를 개선합니다.

**React**

화면 상태와 사용자 인터페이스 관리

**IndexedDB**

프로젝트 데이터 영구 저장

**저장 모듈**

데이터 생성·조회·수정·삭제 및 복원 처리

저장 로직은 UI 코드와 분리합니다.

### 6.2 상품 프로젝트 단위 관리

각 상품은 독립적인 프로젝트로 관리합니다.

프로젝트별 저장 항목:

- 프로젝트 ID
- 프로젝트 이름
- 상품명
- 상품 설명
- 강조할 상품 강점
- 목표 고객층
- 기존 리뷰 데이터
- 기존 리뷰 분석 결과
- AI 생성 가이드
- 수정된 가이드
- 제출 리뷰
- AI 검수 결과
- 프로젝트 생성 시각
- 마지막 수정 시각

### 6.3 저장 기능

1차 구현 완료 기능:

- 프로젝트 생성
- 프로젝트 목록 조회
- 프로젝트 불러오기
- 프로젝트 수정
- 프로젝트 삭제
- 데이터 자동 저장
- 새로고침 후 복원

프로젝트별 데이터가 서로 섞이지 않도록 관리합니다.

### 6.4 저장 시 주의사항

- API 키와 비밀번호는 프로젝트 데이터에 영구 저장하지 않습니다.
- 대량 리뷰 데이터는 `localStorage` 대신 IndexedDB를 우선 검토합니다.
- 저장 실패 및 용량 초과 오류를 처리합니다.
- 브라우저 저장 데이터는 동일한 브라우저 환경에서 유지됩니다.
- 브라우저 데이터 삭제 또는 저장소 초기화 시 데이터가 사라질 수 있습니다.
- 서로 다른 기기 사이의 자동 동기화는 MVP 범위에 포함하지 않습니다.
- 향후 서버 DB 도입을 고려하여 저장소 접근 로직을 독립적으로 구성합니다.

## 7. VS Code 개발 환경 및 실행 방법

### 7.1 실행 환경

Node.js 22.13.0 이상을 사용합니다.

기존 프로젝트 제작 환경은 Node.js 24입니다.

인터넷 연결이 필요합니다.

### 7.2 프로젝트 실행

1. 프로젝트 폴더 `DemandLab`을 VS Code에서 엽니다.
2. VS Code 터미널을 실행합니다.
3. 다음 명령을 입력합니다.

```sh
npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm dev
```

pnpm이 이미 설치되어 있다면 첫 번째 명령은 생략할 수 있습니다.

기본 개발 서버 주소:

`http://localhost:5173`

터미널에 출력된 실제 주소로 접속합니다.

### 7.3 Ollama 로컬 분석 준비

1. Ollama 공식 배포판을 사용자가 직접 설치하고 실행합니다. 앱에서 실행 프로그램을 설치하거나 실행하지 않습니다.
2. Ollama 서버가 실행 중인지 확인합니다. 터미널 실행이 필요한 환경에서는 `ollama serve`를 실행합니다.
3. 분석에 사용할 모델을 직접 선택하여 `ollama pull <모델이름>`으로 내려받습니다. 설치 모델은 `ollama list`로 확인할 수 있습니다.
4. DemandLab을 `pnpm dev`로 실행하고, **AI 연결 설정 → Ollama → 연결 테스트 및 모델 조회**를 누릅니다.
5. 표시된 모델 중 하나를 선택한 뒤 리뷰 분석을 실행합니다.

모델은 설치되어 있다고 가정하지 않습니다. Ollama가 실행되지 않거나 모델이 없다면 화면에서 오류와 안내를 보여줍니다. 이 로컬 프록시는 개발 서버에서만 지원하며 배포된 Cloudflare Worker는 사업자 컴퓨터의 Ollama에 접근할 수 없습니다.

### 7.4 빌드 및 실행

```sh
pnpm build
pnpm start
```

`pnpm build`는 배포용 산출물을 생성합니다.

`pnpm start`는 빌드된 Worker를 로컬에서 실행합니다.

### 7.5 주의사항

이 프로젝트는 일반적인 `next dev` 방식으로 실행하지 않습니다.

기존 프로젝트는 Vinext/Vite 기반 실행 환경을 사용합니다.

`npm ci` 대신 pnpm을 사용합니다.

기존 잠금 파일인 `pnpm-lock.yaml`을 유지합니다.

## 8. 환경변수 및 API 키

### 8.1 현재 구현 방식

OpenAI 키 입력 방식은 AI 연결 설정 화면에서 유지합니다. 제공자는 OpenAI 또는 Ollama를 선택할 수 있습니다.

실제 AI 분석을 실행하려면:

1. 웹사이트에서 AI 연결 설정을 엽니다.
2. OpenAI API 키를 입력합니다.
3. 리뷰 CSV를 업로드하거나 기존 리뷰 프로젝트를 선택합니다.
4. 실제 AI 분석 버튼을 눌러 선택한 제공자로 분석합니다.

현재 서버는 `OPENAI_API_KEY` 환경변수를 읽지 않습니다.

`.env` 파일에 키를 입력하는 것만으로는 AI가 연결되지 않습니다.

### 8.2 현재 API 키 처리

- API 키는 현재 탭의 React 메모리에만 유지됩니다.
- OpenAI 분석·가이드 생성·연결 테스트 요청은 서버 API를 거쳐 OpenAI로 전달됩니다.
- 새로고침하면 입력한 API 키가 사라집니다.
- IndexedDB에 API 키를 저장하지 않습니다. 프로젝트 저장 시 허용된 데이터 필드만 저장합니다.
- Ollama 분석은 로컬 Vinext 개발 서버 API를 거쳐 `127.0.0.1:11434`로 전달됩니다.

### 8.3 AI 연결 방식과 보안 범위

브라우저가 Ollama에 직접 연결하는 대신 같은 출처의 `/api/ai`, `/api/analyze`, `/api/generate-guide` 서버 Route Handler가 로컬 Ollama에 요청합니다. 따라서 브라우저 CORS 설정에 의존하지 않습니다. Ollama 주소를 요청에서 받지 않고 서버 코드의 loopback 주소로 고정해 임의 외부 주소를 향한 SSRF 프록시로 이용되지 않도록 했습니다. API는 현재 출처의 `Origin`도 검사합니다.

이 연결은 `pnpm dev`의 로컬 서버를 전제로 합니다. 실제 배포에서 사용자 로컬 Ollama를 지원하려면 별도 사용자 에이전트/인증/네트워크 설계가 필요합니다.

실제 API 키, 비밀번호, 배포 토큰 등을 소스 코드나 Git 저장소에 포함하지 않습니다.

OpenAI/Ollama 연결 테스트와 모델 목록 조회를 처리합니다.

**`app/api/analyze/route.ts`**

기존 API 경로를 유지하며 선택된 AI 제공자에 리뷰 분석 요청을 전달합니다.

**`app/api/generate-guide/route.ts`**

상품 프로젝트 입력을 검증한 뒤 선택된 AI 제공자에 가이드 생성을 요청하고 프로젝트 저장에 사용할 구조화된 가이드를 반환합니다.

**`components/`**

기존 UI 컴포넌트를 포함합니다.

**`lib/`**

CSV·리뷰 전처리·프로젝트 저장 모듈과 `lib/ai/` 공통 AI 타입·제공자·응답 검증 모듈을 포함합니다.

**`db/`**

기존 DB 관련 기본 코드가 있으며 현재 실제 DB는 사용하지 않습니다.

**`worker/index.ts`**

Cloudflare Worker 실행 진입점입니다.

## 14. 현재 제한 사항

### 14.1 데이터 저장

현재 업로드 리뷰와 분석 결과는 프로젝트별 IndexedDB에 저장하고 새로고침 후 복원합니다.

동일한 브라우저·출처에서만 유지되며, 브라우저 저장 데이터 삭제 시 사라집니다. 서버 백업과 여러 탭/기기의 실시간 동기화는 제공하지 않습니다.

### 14.2 AI 연결

OpenAI와 Ollama는 기존 리뷰 분석, 가이드 생성, 리뷰 검수 작업에 연결되어 있습니다. OpenAI API 키와 실행 중인 Ollama 서버/설치 모델이 필요합니다.

Ollama는 로컬 `pnpm dev` 서버에서만 지원합니다. Cloudflare Worker 배포에서 `127.0.0.1`은 사업자 컴퓨터를 가리키지 않으므로 로컬 모델 분석을 지원하지 않습니다.

검증 당시 `127.0.0.1:11434`에서 Ollama 서버 응답이 없어 실제 연결 및 모델 호출을 종단 간 검증하지 못했습니다.

### 14.3 AI 검증

공통 분석 응답은 JSON 구조, 주제 이름, 결과 필드, 감정 분류, 리뷰 ID 및 원문 근거 포함 여부를 검증합니다. 유효하지 않은 개별 결과는 제외하고, 결과가 누락된 리뷰 ID를 함께 기록합니다. 모든 AI 분류의 정확성을 보장하는 것은 아닙니다.

실제 OpenAI API 키가 없어 이번 작업에서는 성공 호출을 종단 간 검증하지 못했습니다. 테스트는 외부 API를 모의한 자동 테스트로 대신했습니다.

## 27. 7차 구현: 대시보드 UI/UX 및 시연 준비

상품 프로젝트 관리 영역에 IndexedDB에서 읽어온 프로젝트 카드를 추가했습니다. 각 카드에 프로젝트명, 상품명, 타깃 고객, 최근 수정일, 실제 데이터 기반 진행 단계와 리뷰·평가 항목·현재 가이드 검수 수를 표시합니다. 예시·모의 분석 프로젝트는 카드에도 별도 배지를 표시합니다. 대시보드의 단계 내비게이션은 분석 → 가이드 → 검수 화면 이동만 수행하고 저장 데이터는 초기화하지 않습니다.

앱 시작 화면은 프로젝트 대시보드이며, 작업 화면은 상품 정보 → 선택적 기존 리뷰 분석 → AI 가이드 → 리뷰 검수의 네 단계로 구성됩니다. 단계 상태와 이어하기 추천은 실제 프로젝트 저장 데이터를 기준으로 계산합니다. 기존 리뷰 없이도 평가 항목을 설정하면 가이드 단계로 이동할 수 있으며, 작업 화면의 공통 헤더에서 프로젝트와 단계를 바꿀 수 있습니다. 단계 이동 전에 자동 저장을 완료하고, 프로젝트를 바꾸면 검수 화면의 미저장 입력 초안은 새 프로젝트와 섞이지 않도록 초기화합니다.

예시 데이터 버튼은 선택된 프로젝트를 덮어쓰지 않고 무선 이어폰 A 가상 시연 프로젝트를 새로 만듭니다. 상품 설명·타깃·평가 항목·가상 리뷰는 실제 사용자 데이터와 분리되고, 키워드 기반 분석 결과는 모의 데이터로 표시되며 AI의 감정 판단처럼 보이지 않도록 중립·미분석으로 처리합니다. 프로젝트 생성이 실패하면 기존 프로젝트 내용은 수정하지 않습니다.

모바일에서는 프로젝트 카드가 한 열로 배치되고 workflow 단계가 가로 스크롤됩니다. 브라우저에서 기존 프로젝트 3개 표시와 390px 화면의 문서 가로 넘침이 없는 것을 확인했습니다. 시연 프로젝트 생성 후 기존 프로젝트 개수가 그대로 유지되고 상품·타깃·예시 배지가 표시되는 것과 테스트 프로젝트 제거 후 원래 프로젝트로 복귀하는 것도 확인했습니다. 프로젝트 진행 요약, 예시 데이터 플래그, 단계 우선순위 자동 테스트를 추가했고, 최종 자동 테스트 37개·TypeScript·ESLint·프로덕션 빌드가 통과했습니다. 실제 OpenAI/Ollama 호출 및 최종 발표 리허설은 아직 수행하지 않았습니다. 자세한 내용은 [TEST_REPORT.md](./TEST_REPORT.md)를 참고하세요.

### 14.4 리뷰 수집

현재 CSV 파일 업로드만 지원합니다.

쿠팡 상품 링크를 통한 자동 리뷰 수집은 구현되어 있지 않습니다.

### 14.5 리뷰 분석의 한계

AI의 감정 및 주제 분류 정확도는 별도 실험으로 검증하지 않았습니다.

AI가 생성한 분석 결과는 실제 리뷰 원문과 함께 확인해야 합니다.

### 14.6 리뷰 검수의 한계

AI는 리뷰의 텍스트가 가이드를 얼마나 충족하는지 평가할 수 있지만 실제 제품 사용 여부를 직접 검증할 수 없습니다.

리뷰 내용의 진실성이나 협찬·대가성 표시 여부에 대해서는 별도의 확인 절차가 필요할 수 있습니다.

## 16. 기존 프로젝트 인계 및 검증 기록

기존 DemandLab은 CSV 기반 리뷰 분석 서비스로 개발되었습니다.

기존 소스 인계본에서는 화면, 기능, API, 컴포넌트 및 설정을 변경하지 않고 소스 백업을 진행했습니다.

인계 과정에서 다음 사항을 확인했습니다.

- 프로젝트 빌드 성공
- 브라우저 예시 모드 동작
- 주제 및 감정별 원문 필터
- 키워드 검색
- CSV BOM 처리
- 쉼표 및 따옴표 처리
- 다중 행 CSV 처리
- TSV 처리
- 닫히지 않은 따옴표 오류 처리

소스 파일의 해시 비교와 ZIP 구조 검사도 진행되었습니다.

이 검증 기록은 기존 인계본에 대한 것으로, 향후 수정한 코드의 정상 작동을 보증하지 않습니다.

또한 실제 OpenAI API 호출 성공 여부는 별도로 확인해야 합니다.

기존 인계 ZIP에는 실제 API 키, 배포 자격증명 및 Git 이력이 포함되어 있지 않습니다.

## 18. 최종 완료 기준

DemandLab의 MVP는 다음 조건을 충족하면 완료된 것으로 판단합니다.

1. 사업자가 상품 프로젝트를 생성할 수 있습니다.
2. 상품 정보와 강조할 강점, 타깃 고객을 설정할 수 있습니다.
3. 기존 리뷰가 있다면 CSV를 업로드하여 AI 분석을 실행할 수 있습니다.
4. 기존 리뷰가 없어도 상품 정보만으로 가이드를 생성할 수 있습니다.
5. AI가 상품과 타깃에 맞는 리뷰 작성 가이드를 생성할 수 있습니다.
6. 사업자가 가이드를 수정하고 저장할 수 있습니다.
7. 작성된 리뷰를 개별 또는 일괄 업로드할 수 있습니다.
8. AI가 저장된 가이드를 기준으로 리뷰를 검수할 수 있습니다.
9. 리뷰별 검수 결과와 보완 피드백을 확인할 수 있습니다.
10. 프로젝트 데이터가 새로고침 이후에도 유지됩니다.
11. OpenAI API를 이용한 전체 기능이 정상 작동합니다.
12. Ollama 로컬 모델을 이용한 연결 및 지원 기능이 정상 작동합니다.
13. 하나의 샘플 상품으로 처음부터 끝까지 전체 과정을 시연할 수 있습니다.

## 20. 프로젝트 최종 목표

DemandLab은 단순히 리뷰를 분석하는 서비스가 아닙니다.

사업자가 상품의 특징과 목표 고객층을 설정하고, AI가 이를 바탕으로 실질적인 리뷰 작성 가이드를 생성하며, 작성된 리뷰의 품질과 구체성을 검수하는 통합 리뷰단 운영 서비스입니다.

기존 리뷰 분석 기술을 재사용하면서, AI 기반 가이드 생성 및 리뷰 검수 기능을 연결하는 것이 이번 프로젝트의 핵심 개발 목표입니다.

**상품 분석 → 리뷰 가이드 생성 → 리뷰 검수 → 결과 저장**

이 전체 흐름을 안정적으로 구현하는 것을 최우선 목표로 합니다.

## 21. 1차 구현: 프로젝트 저장 (2026-10-30)

프로젝트 이름을 입력하고 **새 프로젝트**를 누른 뒤 기존 CSV 업로드 또는 예시 데이터 기능을 사용합니다. 현재 프로젝트 이름은 바로 수정할 수 있습니다. 변경 후 400ms에 자동 저장하며 프로젝트 전환·생성·삭제 전에는 대기 중인 저장을 완료합니다. 저장 실패 시 전환을 중단하고 다시 시도할 수 있습니다.

- IndexedDB `demandlab` v1: `projects`는 프로젝트 본문, `settings`는 마지막 프로젝트 ID 저장.
- 저장: 리뷰·주제·분석 결과·파일명·CSV 미리보기·열 연결·체험단 제외 설정·분석 모드·안내 문구.
- 임시 상태: 검색어·주제/감정 필터·정렬·페이지·오류·API 키. 프로젝트 전환 시 탐색 조건을 초기화합니다.
- 초기 복원 전 편집을 막으므로 빈 React 상태가 저장 데이터를 덮어쓰지 않습니다. 삭제는 확인창을 거칩니다.
- API 키 처리와 기존 OpenAI 모델/분석 동작은 유지합니다. API JSON 요청·응답 타입 처리를 보완했습니다.
- 같은 출처(프로토콜·호스트·포트)의 브라우저에 저장됩니다. `localhost`와 `127.0.0.1`은 저장소가 다릅니다. 브라우저 데이터 삭제 시 복구되지 않습니다. 기기/탭 간 실시간 동기화는 미구현입니다.
- 닫기 직전 미저장 데이터가 있으면 브라우저에 이탈 경고를 요청합니다. 강제 종료 직전 비동기 저장 완료는 보장하지 않습니다.
- 당시에는 상품 정보, 가이드, 제출 리뷰, 검수 결과 타입만 준비되어 있었습니다. 이후 2~5차 구현에서 각 화면·API·저장 기능을 추가했습니다.

검증 명령: `pnpm test`, `pnpm typecheck`, `pnpm build`.

자동 테스트는 CSV/TSV·따옴표·다중 행·UTF-8/EUC-KR·크기 제한·중복 제거·체험단 탐지·무료 모의 분석을 확인합니다. 브라우저에서는 생성·이름 수정·예시 데이터·검색/필터·무료 모의 분석·새로고침 복원·프로젝트 분리를 확인했습니다. 실제 CSV 업로드는 확장 프로그램의 파일 접근 권한으로, 실제 삭제는 확인창 이후 브라우저 제어 응답 문제로 검증을 완료하지 못했습니다. 실제 OpenAI 호출·용량 초과 오류·강제 종료·다중 탭 동시 수정은 미검증입니다.

## 22. 2차 구현: 상품·타깃 분석 (2026-10-30)

프로젝트 화면에 상품명, 설명, 여러 강점, 목표 고객층, 사용 상황을 추가했습니다. 각 입력은 선택 중인 프로젝트에 자동 저장됩니다. 기존 리뷰는 선택 사항이며, CSV/TSV 파싱·열 연결·중복 제거·체험단 필터·키워드 탐색·OpenAI 분석 API는 기존 구현을 재사용합니다. AI 분석 요청에는 리뷰 본문만 보내며 상품 정보는 보내지 않습니다.

분석 주제 카드에 감정 집계와 리뷰 원문 근거를 표시하고, 주제를 평가 항목으로 추가하거나 직접 항목을 추가·수정·삭제할 수 있습니다. 상품 정보와 리뷰 원본 변경 시 분석 입력 버전을 올려 분석 결과가 오래되었을 수 있음을 표시합니다. 분석 결과와 선택 항목은 현재 IndexedDB 프로젝트에 저장됩니다. 기존 프로젝트는 새 목록 필드를 빈 배열로 복원합니다.

`pnpm test`, `pnpm typecheck`, ESLint 및 프로덕션 빌드를 실행합니다. 브라우저에서 확인한 조작 범위와 실제 OpenAI API 등 미검증 항목은 작업 완료 보고에 기록합니다. 가이드 생성과 리뷰 검수는 이 단계 범위에 포함되지 않습니다.

## 23. 3차 구현: 공통 AI 연결 (2026-10-31)

`lib/ai/types.ts`에 `AIProviderKind`, `AIWorkType`, 리뷰 분석 요청·응답과 제공자 인터페이스를 정의했습니다. `openai.ts`와 `ollama.ts`는 같은 리뷰 분석 요청을 처리하고 `schemas.ts`가 모델별 JSON 내용을 공통 결과로 검증합니다. 실제 연결 작업은 기존 `/api/analyze`를 유지하고 `/api/ai`에서 연결 테스트 및 모델 조회를 제공합니다.

OpenAI는 기본 `gpt-4.1-mini`, 화면 입력 API 키, 서버 측 `/v1/models` 및 `/v1/chat/completions` 호출을 사용합니다. Ollama는 로컬 개발 서버가 고정된 `http://127.0.0.1:11434`에서 `/api/tags`와 `/api/chat`을 호출합니다. 앱은 Ollama를 직접 설치·실행하지 않으며, 배포된 Cloudflare Worker에서 사용자 로컬 Ollama에 접근하지 않습니다. API 키는 메모리에만 유지하고 제공자·모델 설정과 분석 메타데이터만 IndexedDB에 저장합니다.

자동 테스트는 provider 호출을 모의하여 공통 결과 검증, 실제 원문 부분 문자열 검사, 잘못된 감정/리뷰 ID 제외, OpenAI legacy 요청 호환, Ollama loopback 고정, API 오류 및 cross-origin 차단을 확인합니다. 이 환경에는 OpenAI 키가 없고 Ollama도 설치·실행되어 있지 않아 실제 OpenAI/Ollama 분석 성공은 미검증입니다. 가이드 생성·리뷰 검수는 구현하지 않았습니다.

## 24. 4차 구현: AI 리뷰 가이드 생성

`/api/generate-guide`는 프로젝트 상품명·설명·사업자가 확인하고 싶은 강점·타깃·사용 상황·평가 항목과, 존재하는 경우 실제 리뷰 분석 주제·감정 집계·검증된 원문 근거를 받습니다. 예시·모의 분석은 실제 리뷰 근거로 전달하지 않습니다. API는 요청을 검증하고 OpenAI 또는 고정 loopback의 Ollama provider에 공통 작업 타입으로 전달합니다. 모델 응답은 필수 필드, 선택 평가 항목의 포함, 협찬/제품 제공 공개 안내와 위험 테스트 키워드를 검사한 뒤 구조화된 가이드로 반환합니다.

가이드 화면에서 제목·목적·각 테스트의 주제·상황·방법·관찰 항목·질문·체크리스트·작성 안내를 편집하고 테스트 항목을 추가·삭제할 수 있습니다. 현재 프로젝트의 IndexedDB 레코드에 가이드, 생성·수정 시각, provider/model, `guideInputVersion`을 저장합니다. 상품 정보·평가 항목·리뷰 분석 데이터가 바뀌면 저장 가이드는 유지하면서 최신이 아닐 수 있음을 표시합니다. 재생성은 확인을 거치며 실패 응답은 기존 가이드를 교체하지 않습니다. UTF-8 텍스트/Markdown 파일로 다운로드하거나 클립보드에 복사할 수 있습니다.

`pnpm test`는 provider 모의 호출, API 입력/출력 검증, Ollama 고정 주소, 원문 근거 사용, 예시 분석 제외, 가이드 안전·공개 안내 필수 조건 및 텍스트/Markdown 내용을 확인합니다. 해당 시점에는 실제 OpenAI 키와 Ollama 모델 성공 호출을 확인하지 않았으며, 리뷰 검수는 다음 5차 구현에 추가했습니다.

## 25. 5차 구현: AI 리뷰 검수·피드백

`app/review-check-workspace.tsx`에서 상품 프로젝트를 선택하고 단일 리뷰 또는 기존 CSV/TSV 파서로 읽은 리뷰단 초안을 검수 대기 목록에 추가합니다. UTF-8/EUC-KR, 본문 열과 선택 작성자 열, 미리보기, 빈 본문 제외를 지원합니다. 프로젝트당 최대 50건, 리뷰당 6,000자이며 3건씩 순차 요청합니다. 기존 고객 리뷰 분석 workspace와 별개로 저장합니다.

`POST /api/check-review`는 상품 정보, 저장 가이드 및 가이드 버전, 리뷰 배치를 검증하고 선택한 OpenAI/Ollama provider에 전달합니다. 공통 파서는 모델 JSON, 리뷰·가이드 항목 ID, 허용 상태, 원문 내 정확한 근거를 검증하며 필수 항목의 전체 상태를 서버에서 계산합니다. 필수 항목과 가이드에 명시된 관계 공개 안내를 누락하면 보완 필요로 봅니다. 제품 성능·사용 여부·리뷰 진실성은 인증하지 않습니다. Ollama 요청은 기존 로컬 서버에서만 수행합니다.

검수 입력과 결과 시도는 현재 상품 프로젝트의 IndexedDB 레코드에 저장됩니다. 새 가이드로 검수하면 버전이 결과에 기록되고, 실패한 배치는 기존 성공 기록을 덮어쓰지 않으며 실패 건만 다시 요청할 수 있습니다. 결과 목록은 전체·보완 필요·문제 없음·검수 실패로 필터링하고, 리뷰별 근거·상세 피드백을 확인한 뒤 UTF-8 BOM 및 수식 시작 문자 보호를 적용한 CSV로 내보냅니다. 가이드가 없으면 생성 화면으로 이동하도록 안내합니다.

5차 구현 당시 검수 자동 테스트는 입력 제한, 필수/선택 항목 상태, 공개 누락 처리, 존재하지 않는 ID와 원문에 없는 인용 거부, OpenAI/Ollama 모의 호출, loopback 고정, API metadata·키 누락·cross-origin 거부를 확인했습니다. 그 시점에는 브라우저 IndexedDB 전환·새로고침, 파일 선택, 다운로드, 실제 API 키 및 로컬 Ollama 호출을 검증하지 않았습니다. 이후 6차 검증 결과는 다음 절을 참고하세요.

## 26. 6차 통합 검증 및 시연 준비 (2026-10-31)

`pnpm install --frozen-lockfile`, `pnpm test`(34개 통과), `pnpm typecheck`, `pnpm lint`, `pnpm build`를 실행했습니다. 개발 서버가 이미 `127.0.0.1:5173`에서 응답하여 이를 재사용했습니다. 브라우저에서는 명시적으로 가상인 DevDay 임시 프로젝트를 생성하고 상품 입력·저장·프로젝트 전환·새로고침 복원·삭제를 확인했습니다. 기존 리뷰 CSV 열 연결·불러오기·모의 분석 결과와 근거를 확인하고, 평가 주제를 추가했습니다. 모의 생성 API로 가이드를 생성·수정·저장하고 테스트 항목을 편집했습니다. 다른 프로젝트로 전환하는 동안 생성 요청이 끝나도 해당 프로젝트에 가이드가 저장되지 않는 것을 확인했습니다.

검수 화면에서 단일 리뷰와 `tests/fixtures/`의 가상 초안 CSV 3건을 추가해 총 4건을 모의 검수했고, 평가 항목별 근거·피드백과 저장/새로고침 복원을 확인했습니다. 503 실패 시 기존 성공 결과가 남고 실패 건만 재시도할 수 있는 것도 확인했습니다. 추가한 CSV에는 `가상 시연 데이터` 열이 있으며, 실제 고객 리뷰나 제품 성능 자료가 아닙니다. 브라우저 테스트 프로젝트는 종료 전에 삭제했습니다.

OpenAI 설정 UI는 가짜 테스트 키와 모의 연결 응답으로 확인했으며 새로고침 뒤 키 입력이 비어 있음을 확인했습니다. 실제 OpenAI API 호출은 하지 않았습니다. Ollama 실제 연결은 `127.0.0.1:11434`에서 서버 응답이 없어 검증하지 못했습니다. 브라우저 환경에서 Markdown/CSV 다운로드 파일 자체를 수집하지 못했지만, Markdown formatter 및 BOM·CSV 인용·수식 방어는 자동 테스트로 확인했고 다운로드 버튼 동작을 화면에서 호출했습니다. 세부 항목과 미검증 사항은 [TEST_REPORT.md](./TEST_REPORT.md)에 기록했습니다.
