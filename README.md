# DemandLab — AI 기반 리뷰단 운영 서비스

OEG / 컴퓨터공학과 이정경·오지수

2026년 2학기 DevDay 프로젝트

> **프로젝트 상태:** 기존 CSV 리뷰 분석 서비스 구현 완료. AI 기반 리뷰단 운영 서비스로 개편 진행 예정.

---

## 1. 프로젝트 개요

### 1.1 프로젝트 소개

DemandLab은 사업자가 상품의 강점과 타깃 고객을 설정하고, AI가 이를 바탕으로 리뷰단의 실제 사용 테스트 및 리뷰 작성 가이드를 생성하며, 제출된 리뷰를 자동 검수하고 피드백하는 AI 기반 리뷰단 운영 서비스입니다.

기존 고객 리뷰에서 발견한 주요 강점·약점과 고객 관심사를 분석하고, 이를 사업자가 강조하고 싶은 상품 특징 및 타깃 고객 정보와 결합하여 효과적인 리뷰 가이드를 생성합니다.

이후 작성된 리뷰가 가이드에서 요구한 평가 항목을 충분히 다루는지 확인하고 구체적인 보완 피드백을 제공합니다.

### 1.2 프로젝트 목표

상품의 실제 강점과 차별점이 타깃 고객에게 구체적이고 신뢰할 수 있게 전달되도록 리뷰단의 작성 가이드와 검수 과정을 AI로 지원합니다.

본 서비스는 특정한 긍정적 평가를 강요하거나 허위 리뷰를 생성하는 것을 목표로 하지 않습니다.

실제 사용 경험을 바탕으로 상품의 특징을 구체적으로 확인하고 설명하도록 지원하는 것이 핵심입니다.

### 1.3 주요 사용자

- 리뷰단을 운영하는 사업자
- 상품 마케팅 담당자
- 리뷰 캠페인 운영 담당자

### 1.4 개발 목적

2026년 2학기 DevDay 수업 시연용 웹서비스

실제 대규모 리뷰단 운영보다는 주요 AI 기능과 전체 서비스 흐름이 정상적으로 작동하는 MVP 구현을 우선합니다.

## 2. 핵심 기능

DemandLab의 핵심 기능은 다음 세 가지입니다.

### 2.1 상품·타깃 분석

사업자가 상품 정보와 강조하고 싶은 강점, 목표 고객층을 입력하면 AI가 핵심 평가 항목과 적합한 테스트 상황을 제안합니다.

**입력 정보**

- 상품명
- 상품 설명
- 상품의 주요 특징
- 사업자가 강조하고 싶은 강점
- 목표 고객층
- 기존 고객 리뷰 CSV 파일 (선택)

**주요 기능**

- 상품 특징 분석
- 목표 고객층 분석
- 기존 리뷰의 주요 주제 추출
- 주제별 긍정·부정 반응 분석
- 고객 관심사 및 불편 사항 파악
- 핵심 평가 항목 도출
- 적합한 테스트 상황 추천

**출력 결과**

- 상품의 핵심 특징
- 타깃 고객 분석 결과
- 주요 평가 항목
- 추천 테스트 상황
- 기존 리뷰 분석 결과

기존 리뷰 데이터가 없는 신규 상품도 분석 및 가이드 생성이 가능하도록 설계합니다.

### 2.2 AI 리뷰 가이드 생성

상품·타깃 분석 결과를 바탕으로 리뷰단에게 전달할 테스트 및 작성 가이드를 생성합니다.

**주요 기능**

- 상품 특징별 테스트 항목 추천
- 타깃 고객별 사용 상황 제안
- 실제 사용 시 확인할 항목 생성
- 리뷰 작성에 필요한 정보 안내
- 평가 항목 체크리스트 생성
- 생성된 가이드 수정
- 가이드 저장 및 다운로드

**출력 결과**

- 리뷰단 테스트 가이드
- 리뷰 작성 가이드
- 평가 항목 체크리스트

가이드는 긍정적인 평가를 요구하는 방식이 아니라 실제 제품 사용 결과를 구체적으로 기록하도록 안내하는 방식으로 생성합니다.

### 2.3 AI 리뷰 검수·피드백

작성된 리뷰를 저장된 리뷰 가이드와 비교하여 작성 기준 충족 여부를 확인합니다.

**입력 방식**

- 리뷰 한 건 직접 입력
- 리뷰 CSV 파일 일괄 업로드

**주요 기능**

- 가이드 평가 항목 충족 여부 확인
- 사용 경험의 구체성 평가
- 누락된 정보 탐지
- 불명확한 표현 탐지
- 리뷰별 보완 피드백 생성
- 검수 결과 목록 표시
- 검수 결과 저장
- CSV 다운로드

**출력 결과**

- 리뷰별 검수 상태
- 충족한 평가 항목
- 누락된 평가 항목
- 구체적인 보완 피드백

AI 검수는 작성된 텍스트를 바탕으로 판단합니다.

따라서 실제 제품 사용 여부나 리뷰 내용의 진실성을 자동으로 증명할 수는 없습니다.

## 3. 전체 서비스 흐름

1. 사업자가 상품 프로젝트를 생성합니다.
2. 상품명, 특징, 강조할 강점, 목표 고객층을 입력합니다.
3. 필요하다면 기존 리뷰 CSV를 업로드합니다.
4. AI가 상품 정보와 기존 리뷰를 분석합니다.
5. AI가 리뷰단 테스트 및 작성 가이드를 생성합니다.
6. 사업자가 가이드를 확인하고 수정합니다.
7. 리뷰단이 실제 사용 경험을 바탕으로 리뷰를 작성합니다.
8. 사업자가 작성된 리뷰를 업로드합니다.
9. AI가 저장된 가이드를 기준으로 리뷰를 검수합니다.
10. 사업자가 검수 결과와 피드백을 확인합니다.
11. 분석 결과, 가이드, 검수 결과를 프로젝트에 저장합니다.

서비스의 세 가지 핵심 단계는 서로 연결되며, 이전 단계의 결과를 다음 단계에서 활용합니다.

초기 MVP에서는 IndexedDB를 이용한 로컬 저장을 우선 구현합니다.

서버 데이터베이스는 추후 확장 대상으로 분류합니다.

## 5. AI 모델 이중 지원 구조

DemandLab은 OpenAI API와 Ollama 기반 로컬 AI를 선택하여 사용할 수 있도록 설계합니다.

### 5.1 OpenAI API

**현재 상태**

기존 리뷰 분석 API 코드가 구현되어 있습니다.

**주요 특징**

- OpenAI 서버를 통한 AI 분석
- API 키 필요
- 사용량에 따른 비용 발생
- 인터넷 연결 필요

**지원할 기능**

- 상품·타깃 분석
- 리뷰 주제 및 감정 분석
- AI 리뷰 가이드 생성
- AI 리뷰 검수 및 피드백

### 5.2 Ollama

**현재 상태**

개발 예정이며 아직 연결 기능이 구현되지 않았습니다.

**주요 특징**

- 사용자 컴퓨터에서 AI 모델 실행
- OpenAI API 키 없이 사용 가능
- 로컬 컴퓨터의 하드웨어 성능에 영향받음
- 모델을 사전에 설치해야 함

**개발 예정 기능**

- Ollama 서버 연결
- 로컬 모델 선택
- 서버 연결 상태 확인
- AI 분석 요청
- 가이드 생성 및 검수 지원
- 연결 실패 시 오류 안내

기본 Ollama 서버 주소 예시:

`http://localhost:11434`

실제 연결 방식과 모델은 개발 과정에서 확정합니다.

### 5.3 공통 AI 인터페이스

OpenAI API와 Ollama는 서로 다른 호출 방식을 사용하지만, DemandLab 내부에서는 공통 입력 및 출력 형식을 사용하도록 설계합니다.

공통 AI 작업 유형:

1. 상품·타깃 분석
2. 기존 리뷰 분석
3. 리뷰 가이드 생성
4. 리뷰 검수 및 피드백

AI 제공자별 API 호출 로직은 분리합니다.

AI 분석 결과는 동일한 데이터 구조로 변환하여 프론트엔드에 전달합니다.

모델별 응답에 대한 유효성 검사와 오류 처리를 구현합니다.

### 5.4 AI 연결 설정

설정 화면에서 다음 항목을 선택할 수 있도록 개발합니다.

**AI 제공자**

- OpenAI API
- Ollama

**OpenAI 선택 시**

- API 키 입력
- 모델 설정
- 연결 상태 확인

**Ollama 선택 시**

- 로컬 서버 주소
- 사용 가능한 모델 선택
- 연결 상태 확인

AI 제공자를 변경해도 저장된 상품 프로젝트 데이터가 삭제되지 않도록 설계합니다.

### 5.5 AI 모델 비교

향후 동일한 입력 데이터를 사용하여 OpenAI와 Ollama의 성능을 비교할 수 있도록 합니다.

비교 항목:

- 처리 속도
- 분석 결과의 정확성
- 결과의 구체성
- JSON 출력 안정성
- 가이드 생성 품질
- 리뷰 검수 품질

모델 비교는 핵심 기능 완성 이후 진행합니다.

## 6. 데이터 저장 설계

### 6.1 저장 방식

현재 React 상태에만 데이터를 저장하는 구조를 개선합니다.

**React**

화면 상태와 사용자 인터페이스 관리

**IndexedDB**

프로젝트 데이터 영구 저장

**저장 모듈**

데이터 생성·조회·수정·삭제 및 복원 처리

저장 로직은 UI 코드와 분리합니다.

### 6.2 상품 프로젝트 단위 관리

각 상품은 독립적인 프로젝트로 관리합니다.

프로젝트별 저장 항목:

- 프로젝트 ID
- 프로젝트 이름
- 상품명
- 상품 설명
- 강조할 상품 강점
- 목표 고객층
- 기존 리뷰 데이터
- 기존 리뷰 분석 결과
- AI 생성 가이드
- 수정된 가이드
- 제출 리뷰
- AI 검수 결과
- 프로젝트 생성 시각
- 마지막 수정 시각

### 6.3 저장 기능

개발 예정 기능:

- 프로젝트 생성
- 프로젝트 목록 조회
- 프로젝트 불러오기
- 프로젝트 수정
- 프로젝트 삭제
- 데이터 자동 저장
- 새로고침 후 복원

프로젝트별 데이터가 서로 섞이지 않도록 관리합니다.

### 6.4 저장 시 주의사항

- API 키와 비밀번호는 프로젝트 데이터에 영구 저장하지 않습니다.
- 대량 리뷰 데이터는 `localStorage` 대신 IndexedDB를 우선 검토합니다.
- 저장 실패 및 용량 초과 오류를 처리합니다.
- 브라우저 저장 데이터는 동일한 브라우저 환경에서 유지됩니다.
- 브라우저 데이터 삭제 또는 저장소 초기화 시 데이터가 사라질 수 있습니다.
- 서로 다른 기기 사이의 자동 동기화는 MVP 범위에 포함하지 않습니다.
- 향후 서버 DB 도입을 고려하여 저장소 접근 로직을 독립적으로 구성합니다.

## 7. VS Code 개발 환경 및 실행 방법

### 7.1 실행 환경

Node.js 22.13.0 이상을 사용합니다.

기존 프로젝트 제작 환경은 Node.js 24입니다.

인터넷 연결이 필요합니다.

### 7.2 프로젝트 실행

1. 프로젝트 폴더 `DemandLab`을 VS Code에서 엽니다.
2. VS Code 터미널을 실행합니다.
3. 다음 명령을 입력합니다.

```sh
npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm dev
```

pnpm이 이미 설치되어 있다면 첫 번째 명령은 생략할 수 있습니다.

기본 개발 서버 주소:

`http://localhost:5173`

터미널에 출력된 실제 주소로 접속합니다.

### 7.3 빌드 및 실행

```sh
pnpm build
pnpm start
```

`pnpm build`는 배포용 산출물을 생성합니다.

`pnpm start`는 빌드된 Worker를 로컬에서 실행합니다.

### 7.4 주의사항

이 프로젝트는 일반적인 `next dev` 방식으로 실행하지 않습니다.

기존 프로젝트는 Vinext/Vite 기반 실행 환경을 사용합니다.

`npm ci` 대신 pnpm을 사용합니다.

기존 잠금 파일인 `pnpm-lock.yaml`을 유지합니다.

## 8. 환경변수 및 API 키

### 8.1 현재 구현 방식

현재 프로젝트는 OpenAI API 키를 화면에서 직접 입력하는 방식입니다.

실제 AI 분석을 실행하려면:

1. 웹사이트에서 AI 연결 설정을 엽니다.
2. OpenAI API 키를 입력합니다.
3. 리뷰 CSV를 업로드합니다.
4. AI 분석 시작 버튼을 누릅니다.

현재 서버는 `OPENAI_API_KEY` 환경변수를 읽지 않습니다.

`.env` 파일에 키를 입력하는 것만으로는 AI가 연결되지 않습니다.

### 8.2 현재 API 키 처리

- API 키는 현재 탭의 React 메모리에만 유지됩니다.
- 분석 요청 시 서버 API를 거쳐 OpenAI에 전달됩니다.
- 새로고침하면 입력한 API 키가 사라집니다.
- 데이터베이스에 API 키를 저장하지 않습니다.

### 8.3 향후 개선 사항

- AI 제공자 선택 기능
- OpenAI API 연결 설정 개선
- Ollama 로컬 서버 연결
- 제공자별 오류 처리
- 비밀정보의 안전한 처리

실제 API 키, 비밀번호, 배포 토큰 등을 소스 코드나 Git 저장소에 포함하지 않습니다.

## 14. 현재 제한 사항

### 14.1 데이터 저장

현재 업로드 리뷰와 분석 결과는 React 메모리에만 유지됩니다.

새로고침하면 데이터가 사라집니다.

IndexedDB 저장 기능은 개발 예정입니다.

### 14.2 AI 연결

현재 실제 분석 API는 OpenAI 기반으로 구현되어 있습니다.

Ollama 연결은 아직 구현되지 않았습니다.

### 14.3 AI 검증

기존 AI API는 JSON 응답을 요구하며 일부 필드를 검증합니다.

그러나 모든 비정상 응답을 완벽하게 검증하지는 않습니다.

실제 OpenAI API 성공 응답은 기존 소스 제작 당시 API 키가 없어 종단 간 검증하지 못했습니다.

### 14.4 리뷰 수집

현재 CSV 파일 업로드만 지원합니다.

쿠팡 상품 링크를 통한 자동 리뷰 수집은 구현되어 있지 않습니다.

### 14.5 리뷰 분석의 한계

AI의 감정 및 주제 분류 정확도는 별도 실험으로 검증하지 않았습니다.

AI가 생성한 분석 결과는 실제 리뷰 원문과 함께 확인해야 합니다.

### 14.6 리뷰 검수의 한계

AI는 리뷰의 텍스트가 가이드를 얼마나 충족하는지 평가할 수 있지만 실제 제품 사용 여부를 직접 검증할 수 없습니다.

리뷰 내용의 진실성이나 협찬·대가성 표시 여부에 대해서는 별도의 확인 절차가 필요할 수 있습니다.

## 16. 기존 프로젝트 인계 및 검증 기록

기존 DemandLab은 CSV 기반 리뷰 분석 서비스로 개발되었습니다.

기존 소스 인계본에서는 화면, 기능, API, 컴포넌트 및 설정을 변경하지 않고 소스 백업을 진행했습니다.

인계 과정에서 다음 사항을 확인했습니다.

- 프로젝트 빌드 성공
- 브라우저 예시 모드 동작
- 주제 및 감정별 원문 필터
- 키워드 검색
- CSV BOM 처리
- 쉼표 및 따옴표 처리
- 다중 행 CSV 처리
- TSV 처리
- 닫히지 않은 따옴표 오류 처리

소스 파일의 해시 비교와 ZIP 구조 검사도 진행되었습니다.

이 검증 기록은 기존 인계본에 대한 것으로, 향후 수정한 코드의 정상 작동을 보증하지 않습니다.

또한 실제 OpenAI API 호출 성공 여부는 별도로 확인해야 합니다.

기존 인계 ZIP에는 실제 API 키, 배포 자격증명 및 Git 이력이 포함되어 있지 않습니다.

DemandLab의 MVP는 다음 조건을 충족하면 완료된 것으로 판단합니다.

1. 사업자가 상품 프로젝트를 생성할 수 있습니다.
2. 상품 정보와 강조할 강점, 타깃 고객을 설정할 수 있습니다.
3. 기존 리뷰가 있다면 CSV를 업로드하여 AI 분석을 실행할 수 있습니다.
4. 기존 리뷰가 없어도 상품 정보만으로 가이드를 생성할 수 있습니다.
5. AI가 상품과 타깃에 맞는 리뷰 작성 가이드를 생성할 수 있습니다.
6. 사업자가 가이드를 수정하고 저장할 수 있습니다.
7. 작성된 리뷰를 개별 또는 일괄 업로드할 수 있습니다.
8. AI가 저장된 가이드를 기준으로 리뷰를 검수할 수 있습니다.
9. 리뷰별 검수 결과와 보완 피드백을 확인할 수 있습니다.
10. 프로젝트 데이터가 새로고침 이후에도 유지됩니다.
11. OpenAI API를 이용한 전체 기능이 정상 작동합니다.
12. Ollama 로컬 모델을 이용한 연결 및 지원 기능이 정상 작동합니다.
13. 하나의 샘플 상품으로 처음부터 끝까지 전체 과정을 시연할 수 있습니다.

## 19. 개발 문서 관리

프로젝트 관련 문서는 다음과 같이 구분합니다.

**README.md**

프로젝트 소개, 기술 스택, 실행 방법, 구현 현황 및 주요 제한 사항을 기록합니다.

**PROJECT_PLAN.md**

상세 기능 요구사항, 데이터 구조, 개발 단계, 작업 우선순위 및 진행 체크리스트를 관리합니다.

**SOURCE_HANDOFF.md (선택)**

기존 프로젝트의 소스 인계 정보와 원본 검증 기록을 보존합니다.

기능이 구현되거나 기술 구조가 변경되면 관련 문서를 함께 업데이트합니다.

## 20. 프로젝트 최종 목표

DemandLab은 단순히 리뷰를 분석하는 서비스가 아닙니다.

사업자가 상품의 특징과 목표 고객층을 설정하고, AI가 이를 바탕으로 실질적인 리뷰 작성 가이드를 생성하며, 작성된 리뷰의 품질과 구체성을 검수하는 통합 리뷰단 운영 서비스입니다.

기존 리뷰 분석 기술을 재사용하면서, AI 기반 가이드 생성 및 리뷰 검수 기능을 연결하는 것이 이번 프로젝트의 핵심 개발 목표입니다.

**상품 분석 → 리뷰 가이드 생성 → 리뷰 검수 → 결과 저장**

이 전체 흐름을 안정적으로 구현하는 것을 최우선 목표로 합니다.
